1描述符是什么

一句话定义 描述符协议让你拦截"属性访问/赋值/删除"的行为，把一个类的属性变成"有逻辑的代理"。

简单来说：如果一个类实现了 __get__、__set__、__delete__ 中的任意一个，它的实例作为另一个类的类属性时，就变成了描述符——访问该属性时不会直接取值，而是调用这些方法。

# 描述符的基本结构 class MyDescriptor: def __get__(self, obj, objtype=None): # 拦截 obj.attr 或 Class.attr 的读取 ... def __set__(self, obj, value): # 拦截 obj.attr = value 的赋值 ... def __delete__(self, obj): # 拦截 del obj.attr 的删除 ... class MyClass: attr = MyDescriptor() # ← attr 就是一个描述符
关键认知 Python 中 property、classmethod、staticmethod、super() 底层全是描述符。理解描述符 = 理解 Python 面向对象的底层机制。

2三个核心方法

方法 触发时机 参数说明
__get__(self, obj, objtype) obj.attr 或 Class.attr obj 是实例（类访问时为 None），objtype 是类
__set__(self, obj, value) obj.attr = value value 是要赋的值
__delete__(self, obj) del obj.attr —
__set_name__(self, owner, name) 类定义时自动调用 owner 是所属类，name 是属性名（Python 3.6+）

参数详解

class MyDescriptor: def __get__(self, obj, objtype=None): # self: 描述符实例本身 # obj: 使用描述符的实例（实例访问时），类访问时为 None # objtype: 使用描述符的类 if obj is None: return self # 类级别访问 → 返回描述符自身 return obj.__dict__.get('_value') def __set__(self, obj, value): # self: 描述符实例 # obj: 使用描述符的实例 # value: 要赋的值 obj.__dict__['_value'] = value

3数据描述符 vs 非数据描述符 高频

类型 实现方法 优先级 典型代表
数据描述符 __get__ + __set__ 或 __delete__ 最高（高于实例字典） property、ORM 字段
非数据描述符 仅 __get__ 较低（低于实例字典） 普通方法、classmethod、staticmethod

代码验证优先级差异

class Data: def __get__(self, obj, objtype=None): return "data" def __set__(self, obj, value): pass # ← 有 __set__ → 数据描述符 class NonData: def __get__(self, obj, objtype=None): return "nondata" # ← 没有 __set__ → 非数据描述符 class C: data = Data() nondata = NonData() c = C() c.__dict__['data'] = '实例字典的值' # 手动往实例字典塞值 c.__dict__['nondata'] = '实例字典的值' print(c.data) # "data" ← 数据描述符赢，实例字典被忽略 print(c.nondata) # "实例字典的值" ← 实例字典赢，__get__ 被跳过

4为什么只有 __get__ 是非数据描述符 高频

核心原因 有 __set__ 说明你声明了"我要控制赋值"，Python 就给你最高优先级，防止实例字典绕过校验逻辑。只有 __get__ 说明"我只管读取，赋值你随意"，实例一旦赋值就进实例字典，自然就盖过了 __get__。

赋值时的行为差异

class Data: def __get__(self, obj, objtype=None): return "data" def __set__(self, obj, value): print(f"设置值: {value}") class NonData: def __get__(self, obj, objtype=None): return "nondata" class C: data = Data() nondata = NonData() c = C() c.data = 100 # Data 有 __set__ → Python 调用 Data.__set__(c, 100) → 拦截赋值 # → 实例字典不会被写入 c.nondata = 100 # NonData 没有 __set__ → Python 不知道要拦截 # → 直接写入实例字典 c.__dict__['nondata'] = 100 # → 下次读取时实例字典有值，就不再走 __get__ 了

设计哲学：保护 vs 灵活

数据描述符 = "我要完全控制这个属性" 有 __set__ 说明你声明了赋值控制权，Python 让你优先级高于实例字典，保证不会被绕过。
例：property 有 setter 校验逻辑，如果不给最高优先级，obj.__dict__['temp'] = -300 就能绕过校验。
非数据描述符 = "我只管读取，赋值你随意" 没有 __set__ 说明不控制赋值，实例一旦赋值就直接进字典，自然覆盖描述符。
例：普通方法（function）只有 __get__，允许 obj.method = custom_func 覆盖，这是合理的灵活性。
有 __set__ 没有 __set__
赋值 c.x = 100 被 __set__ 拦截 直接写入实例字典
实例字典有没有值 __set__ 控制，可能不写入 一定写入
读取时谁优先 描述符优先（防止被绕过） 实例字典优先（覆盖描述符）

5属性查找的完整流程 高频

三层结构（不是全程走 MRO！） 属性查找 = 三个独立的层，顺序执行。__mro__ 只在第①层和第③层使用，第②层实例字典是独立的，跟继承链完全无关。
obj.x 的查找过程： ① MRO 搜索「数据描述符」 (沿 __mro__ 遍历) └─ 有 __get__ + __set__/__delete__？ ├─ 是 → 调用 __get__(obj, type(obj))，返回，结束 └─ 否 → 继续 ② 实例字典 (不走 MRO! 直接查 obj.__dict__) └─ name in obj.__dict__？ ├─ 是 → 返回 obj.__dict__[name]，结束 └─ 否 → 继续 ③ MRO 搜索「非数据描述符 + 普通类属性」 (沿 __mro__ 遍历) └─ name in klass.__dict__？ ├─ 有 __get__ → 调用 __get__(obj, type(obj))，返回 ├─ 普通属性 → 直接返回 └─ 没有 → 继续 ④ 都没找到 → raise AttributeError

伪代码实现

def attribute_lookup(obj, name): cls = type(obj) mro = cls.__mro__ # ① 沿 MRO 找数据描述符 for klass in mro: attr = klass.__dict__.get(name) if attr is not None and hasattr(attr, '__set__'): return attr.__get__(obj, cls) # ② 查实例字典（不经过 MRO！） if name in obj.__dict__: return obj.__dict__[name] # ③ 沿 MRO 找非数据描述符和普通属性 for klass in mro: if name in klass.__dict__: attr = klass.__dict__[name] if hasattr(attr, '__get__'): return attr.__get__(obj, cls) return attr # ④ 没找到 raise AttributeError(name)

用例子一步步走一遍

c.data 的查找（数据描述符）

# C.__mro__ = (C, object) # ① MRO 找数据描述符 # C.__dict__['data'] → Data() → 有 __set__？✅ 是数据描述符！ # → 调用 Data.__get__(c, C) → 返回 "data" # → 结束，根本没走到第②层 print(c.data) # "data" ← 第①层就命中

c.nondata 的查找（非数据描述符）

# C.__mro__ = (C, object) # ① MRO 找数据描述符 # C.__dict__['nondata'] → NonData() → 有 __set__？❌ 没有 # → 第①层没命中 # ② 查实例字典（跟 MRO 无关！） # c.__dict__['nondata'] = '实例字典的值' → ✅ 找到了！ # → 返回 '实例字典的值' print(c.nondata) # "实例字典的值" ← 第②层命中
常见误区 不要把"属性查找"理解成"全程沿 __mro__ 走"。实例字典是独立的一层，跟继承链完全无关，夹在数据描述符和非数据描述符之间。

6__mro__ 与属性查找的关系

什么是 __mro__

__mro__ = Method Resolution Order（方法解析顺序），是 Python 用 C3 线性化算法算出的继承链排队顺序，决定了属性/方法从哪个父类找。本质是一个元组，不可变。

class A: pass class B(A): pass class C(A): pass class D(B, C): pass print(D.__mro__) # (D, B, C, A, object) # ↑ 自己永远在第一位

C3 线性化核心原则

  1. 子类在父类前面（D 在 B、C、A 前面）
  2. 继承顺序保持（B 在 C 前面，因为 class D(B, C)）
  3. 每个类只出现一次

super() 的关键认知

super() 不是"调用父类" super() 是"调用 __mro__ 中的下一个类"。理解这一点是理解 Python 多继承的关键。
# D.__mro__ = (D, B, C, A, object) class D(B, C): def __init__(self): super().__init__() # → 调用 B.__init__（MRO中D的下一个） class B(A): def __init__(self): super().__init__() # → 调用 C.__init__（不是 A！） class C(A): def __init__(self): super().__init__() # → 调用 A.__init__

这就是为什么多继承下 super() 能让所有类的 __init__ 都被调用一次且仅一次——靠的就是 __mro__ 这个线性顺序。

7property 的本质就是描述符

你写的 @property 底层就是一个数据描述符：

# 你写的 property class C: @property def x(self): return self._x @x.setter def x(self, value): self._x = value # 底层等价于 class C: def get_x(self): return self._x def set_x(self, value): self._x = value x = property(get_x, set_x) # property 实现了 __get__ 和 __set__

property 源码简化版

class property: def __init__(self, fget=None, fset=None, fdel=None): self.fget = fget self.fset = fset def __get__(self, obj, objtype=None): if obj is None: return self return self.fget(obj) def __set__(self, obj, value): self.fset(obj, value)
面试要点 property 有 __set__ → 数据描述符 → 优先级高于实例字典 → 不能被实例字典覆盖。这就是为什么 property 能强制执行校验逻辑。

8实战：ORM 字段实现

描述符的经典应用场景：封装字段校验逻辑，一次封装，处处复用。

class Field: def __set_name__(self, owner, name): self.name = name self.storage_name = f'_{name}' def __get__(self, obj, objtype=None): if obj is None: return self return getattr(obj, self.storage_name, None) def __set__(self, obj, value): self.validate(value) setattr(obj, self.storage_name, value) def validate(self, value): raise NotImplementedError class CharField(Field): def __init__(self, max_length=255): self.max_length = max_length def validate(self, value): if not isinstance(value, str): raise TypeError(f"{self.name} 需要字符串") if len(value) > self.max_length: raise ValueError(f"{self.name} 超过 {self.max_length} 字符") class IntegerField(Field): def validate(self, value): if not isinstance(value, int): raise TypeError(f"{self.name} 需要整数") # 使用：三个字段共享一套校验机制 class User(Model): name = CharField(max_length=50) age = IntegerField() user = User() user.name = "Alice" # ✅ user.name = "A" * 100 # ❌ ValueError: name 超过 50 字符 user.age = "abc" # ❌ TypeError: age 需要整数
实际项目对应 Django ORM 的 Model、SQLAlchemy、Peewee 都用描述符把类属性转成数据库列定义。Pydantic V1 也用描述符收集字段。

9实战：Agent 配置类型校验 Agent

在 Agent 开发中，用描述符实现配置属性的自动类型校验：

class TypedField: def __init__(self, type_): self.type_ = type_ def __set_name__(self, owner, name): self.name = name def __get__(self, obj, objtype=None): if obj is None: return self return obj.__dict__.get(self.name) def __set__(self, obj, value): if not isinstance(value, self.type_): raise TypeError( f"{self.name} 需要 {self.type_.__name__}，" f"传入了 {type(value).__name__}" ) obj.__dict__[self.name] = value class AgentConfig: model = TypedField(str) temperature = TypedField(float) max_tokens = TypedField(int) tools = TypedField(list) config = AgentConfig() config.model = "gpt-4" # ✅ config.model = 123 # ❌ TypeError config.temperature = 0.7 # ✅ config.temperature = "hot" # ❌ TypeError

10Python 中哪些地方用了描述符 追问

场景 描述符类型 说明
@property 数据描述符 有 __get__ + __set__
@classmethod 非数据描述符 只有 __get__，返回绑定方法
@staticmethod 非数据描述符 只有 __get__，返回普通函数
super() 数据描述符 底层依赖描述符机制实现 MRO 跳转
普通方法 def method(self) 非数据描述符 function 有 __get__，无 __set__
ORM 字段（Django/SQLAlchemy） 数据描述符 字段校验 + 惰性加载
Pydantic V1 字段 数据描述符 类型校验（V2 改用 Rust + __init_subclass__）
__slots__ 底层依赖描述符机制 阻止实例字典创建，改为 slot 描述符

11面试问答速查

Q1: 什么是描述符协议？
描述符协议是 Python 属性访问的底层机制，本质是把属性访问委托给一个有 __get__/__set__/__delete__ 的对象。它让属性从"直接存取值"变成"有逻辑的代理"，实现校验、惰性计算、类型检查等。
Q2: 数据描述符和非数据描述符的区别？
数据描述符有 __set__ 或 __delete__，优先级高于实例字典；非数据描述符只有 __get__，优先级低于实例字典。有 __set__ 说明声明了"我要控制赋值"，Python 就给你最高优先级防止被绕过。
Q3: 属性查找的完整流程？
三层接力：① 沿 MRO 找数据描述符 → ② 查实例字典（不走 MRO）→ ③ 沿 MRO 找非数据描述符和普通属性。实例字典能盖住非数据描述符（排在它前面），但盖不住数据描述符（排在它后面）。
Q4: 为什么只有 __get__ 是非数据描述符？
分类依据不是"有没有 __get__"，而是"有没有声明赋值控制权"。没有 __set__ 的描述符无法拦截赋值，实例一旦赋值就直接进实例字典，自然就盖过了 __get__。本质是 Python 对"保护性 vs 灵活性"的权衡。
Q5: __mro__ 是什么？
Method Resolution Order，方法解析顺序。Python 用 C3 线性化算法算出的继承链排队顺序，本质是一个元组，包含自己（自己在第一位）和所有祖先类。super() 不是"调用父类"，而是"调用 MRO 中的下一个类"。
Q6: property 的本质是什么？
property 是 Python 内置的数据描述符类，实现了 __get__ 和 __set__。因为有 __set__，它是数据描述符，优先级高于实例字典，所以不能被实例字典覆盖，校验逻辑不会被绕过。
Q7: 描述符有什么实际用途？
① 属性校验（ORM 字段、类型检查）② 惰性计算（首次访问时计算并缓存）③ 日志/监控（拦截访问行为）④ ORM 列定义（Django/SQLAlchemy）⑤ 配置管理（Agent 配置类型校验）。核心价值是"一次封装，处处复用"。
Q8: __set_name__ 是什么？什么时候调用？
Python 3.6 引入，在类定义时自动调用，参数是 (owner, name)——所属类和属性名。有了它就不需要手动传属性名字符串，描述符能自动知道自己在类中叫什么。
