一、Python 基础概念
高频1. Python 中可变类型和不可变类型有哪些？区别是什么？

不可变类型（Immutable）：创建后值不可修改，修改时会创建新对象。

  • int, float, bool, str, tuple, frozenset, bytes

可变类型（Mutable）：创建后可以原地修改，对象 id 不变。

  • list, dict, set, bytearray

关键区别：函数传参时，不可变类型在函数内修改会创建新对象（不影响外部）；可变类型在函数内原地修改会影响外部引用。

def modify_list(lst):
    lst.append(4)  # 原地修改，外部可见

def modify_int(n):
    n += 1      # 创建新对象，外部不可见

a = [1, 2, 3]
modify_list(a)
print(a)  # [1, 2, 3, 4]

b = 10
modify_int(b)
print(b)  # 10
面试追问点：为什么 dict 的 key 必须是可哈希的（即不可变类型）？因为 dict 用哈希表实现，key 的哈希值在生命周期内必须不变，否则无法正确定位。
高频2. is 和 == 的区别？

is 比较两个对象的 id（内存地址）是否相同，即身份比较。

== 比较两个对象的 值 是否相等，即值比较（调用 __eq__ 方法）。

a = 256
b = 256
a is b  # True — Python 对 -5~256 的小整数做了缓存

c = 257
d = 257
c is d  # False — 超出缓存范围，是不同对象
c == d  # True  — 值相等

e = [1, 2, 3]
f = [1, 2, 3]
e is f  # False
e == f  # True
注意：None 比较应该用 if x is None 而不是 if x == None，因为 None 是单例对象。
高频3. 深拷贝和浅拷贝的区别？

浅拷贝：创建新对象，但内部嵌套的可变对象仍引用同一地址。

  • 方式：copy.copy()、list.copy()、dict.copy()、切片 lst[:]

深拷贝：递归拷贝所有层级的对象，完全独立。

  • 方式：copy.deepcopy()
import copy

original = [[1, 2], [3, 4]]

shallow = copy.copy(original)
shallow[0].append(99)
print(original)  # [[1, 2, 99], [3, 4]] — 内层被修改！

original2 = [[1, 2], [3, 4]]
deep = copy.deepcopy(original2)
deep[0].append(99)
print(original2)  # [[1, 2], [3, 4]] — 不受影响
操作外层对象内层可变对象
浅拷贝新对象共享引用
深拷贝新对象递归新建
赋值 (=)共享引用共享引用
高频4. *args 和 **kwargs 的作用？

*args：接收任意数量的位置参数，打包成 tuple。

**kwargs：接收任意数量的关键字参数，打包成 dict。

def func(*args, **kwargs):
    print(type(args))    # <class 'tuple'>
    print(type(kwargs)) # <class 'dict'>

func(1, 2, 3, name="Alice", age=25)
# args = (1, 2, 3)
# kwargs = {'name': 'Alice', 'age': 25}

# 解包用法
nums = [1, 2, 3]
print(range(*nums))  # 等价于 range(1, 2, 3)
参数顺序：位置参数 → *args → 默认参数 → **kwargs。
def f(a, b, *args, c=10, **kwargs)
高频5. 装饰器的原理和常见用法？

装饰器本质是一个高阶函数，接收函数作为参数，返回一个新函数（或可调用对象），在不修改原函数代码的前提下扩展其功能。

原理：@decorator 等价于 func = decorator(func)。

import functools

# 基础装饰器
def log(func):
    @functools.wraps(func)  # 保留原函数元信息
    def wrapper(*args, **kwargs):
        print(f"调用 {func.__name__}")
        result = func(*args, **kwargs)
        print(f"完成 {func.__name__}")
        return result
    return wrapper

@log
def hello():
    print("Hello!")

# 带参数的装饰器（三层嵌套）
def repeat(n):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(n):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def greet():
    print("Hi!")  # 打印3次

常见应用场景（与 Agent 开发相关）：

  • 日志记录 / 耗时统计
  • 重试机制（retry decorator）
  • 缓存（@functools.lru_cache）
  • 权限校验 / 鉴权
  • 限流（rate limiting）
面试追问：@functools.wraps 的作用？—— 保留被装饰函数的 __name__、__doc__ 等元信息，避免反射出 wrapper 的名字。
高频6. 生成器与迭代器的区别？yield 的原理？

迭代器（Iterator）：实现了 __iter__() 和 __next__() 的对象，遵循迭代器协议。

生成器（Generator）：一种特殊的迭代器，使用 yield 关键字自动实现迭代器协议，代码更简洁。

对比迭代器生成器
实现方式手动实现 __iter__/__next__用 yield 关键字
代码量较多少
状态保存手动管理自动暂停/恢复
内存惰性计算惰性计算
# 生成器函数
def counter(max_n):
    n = 0
    while n < max_n:
        yield n   # 暂停执行，返回值；下次 next() 时恢复
        n += 1

gen = counter(3)
print(next(gen))  # 0
print(next(gen))  # 1
print(next(gen))  # 2
# print(next(gen))  # StopIteration

# 生成器表达式
squares = (x**2 for x in range(1000000))
# 不会一次性生成100万个数，按需计算，节省内存
Agent 开发场景：处理大量 LLM 流式输出（streaming）时，生成器是核心模式——逐 token 返回，避免等待全部生成。
高频7. 闭包是什么？有什么应用？

闭包：一个内部函数引用了外部函数的变量，且外部函数已返回，该变量仍被保留在内存中。闭包 = 函数 + 其引用的环境变量。

三个条件：① 有嵌套函数；② 内部函数引用外部变量；③ 外部函数返回内部函数。

def make_multiplier(factor):
    # factor 被内部函数"捕获"，形成闭包
    def multiply(n):
        return n * factor
    return multiply

double = make_multiplier(2)
print(double(5))  # 10
# make_multiplier 已返回，但 factor=2 仍存活

# 闭包经典陷阱：循环中的延迟绑定
funcs = []
for i in range(3):
    funcs.append(lambda: i)  # 闭包引用的是变量 i，不是值

print([f() for f in funcs])  # [2, 2, 2] 而非 [0, 1, 2]

# 修复：用默认参数绑定当前值
funcs2 = [lambda i=i: i for i in range(3)]
print([f() for f in funcs2])  # [0, 1, 2]
高频8. 上下文管理器（with 语句）的原理？

with 语句用于资源管理（文件、锁、连接等），确保资源被正确释放。需要对象实现 上下文管理协议：__enter__() 和 __exit__()。

# 方式一：实现 __enter__ / __exit__
class DatabaseConnection:
    def __enter__(self):
        print("连接数据库")
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        print("关闭连接")
        # 返回 True 则吞掉异常，返回 False/None 则向上抛
        return False

with DatabaseConnection() as db:
    print("使用数据库")
# 即使内部抛异常，__exit__ 也会被调用

# 方式二：使用 contextlib.contextmanager
from contextlib import contextmanager

@contextmanager
def db_connection():
    print("连接数据库")
    try:
        yield "db_obj"
    finally:
        print("关闭连接")
Agent 场景：管理 LLM API 客户端生命周期、数据库 session、异步锁等，都依赖上下文管理器。
高频9. Python 中的作用域 LEGB 规则？

Python 查找变量时遵循 LEGB 优先级顺序：

层级名称说明
LLocal当前函数内部
EEnclosing外层嵌套函数（闭包）
GGlobal模块级别
BBuilt-in内置命名空间（print, len 等）

赋值操作默认创建局部变量。如需在函数内修改全局变量，需用 global；修改闭包变量用 nonlocal。

x = "global"

def outer():
    y = "enclosing"
    def inner():
        global x       # 修改全局 x
        nonlocal y   # 修改外层 y
        x = "modified"
        y = "modified"
    inner()

二、面向对象编程
高频1. Python 的 MRO（方法解析顺序）是什么？

MRO（Method Resolution Order）决定了多继承中方法查找的顺序。Python 3 使用 C3 线性化算法，保证：

  • 子类在父类之前
  • 多个父类按声明顺序排列
  • 保持单调性（不会重复出现在不同位置之间）
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print(D.__mro__)
# (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)

# super() 实际上调用的是 MRO 中的下一个类，不一定是"父类"
# 在 D 的方法中 super() 指向 B，在 B 的方法中 super() 指向 C
面试关键：super() 不是简单地调用父类，而是按 MRO 顺序调用下一个类的方法。这就是协作多继承（cooperative multiple inheritance）的核心。
高频2. Python 如何实现抽象类和接口？

Python 使用 abc 模块（Abstract Base Classes）实现抽象类：

from abc import ABC, abstractmethod

class BaseAgent(ABC):
    @abstractmethod
    def plan(self, task: str):
        """子类必须实现"""
        pass

    @abstractmethod
    def execute(self, action: str):
        pass

    def run(self):
        """具体方法，子类可直接继承"""
        plan = self.plan("task")
        self.execute(plan)

# 不能实例化抽象类
# agent = BaseAgent()  # TypeError

class LLMAgent(BaseAgent):
    def plan(self, task):
        return f"Planning: {task}"

    def execute(self, action):
        print(f"Executing: {action}")

agent = LLMAgent()
agent.run()
Python 没有正式的 interface 关键字。抽象类 + 多继承 = 接口的效果。也可以用 Protocol（typing 模块）实现结构化子类型（鸭子类型的类型安全版本）。

高频4. @property 装饰器的作用？

将方法转换为只读属性，支持 getter/setter/deleter，实现受控的属性访问。

class Temperature:
    def __init__(self, celsius):
        self._celsius = celsius

    @property
    def fahrenheit(self):
        return self._celsius * 9 / 5 + 32

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("低于绝对零度")
        self._celsius = value

t = Temperature(25)
print(t.fahrenheit)  # 77.0 — 像属性一样访问
t.celsius = 30         # 调用 setter

高频6. Python 单例模式的实现方式？
# 方式一：__new__ 实现
class Singleton:
    _instance = None
    _initialized = False

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self):
        if not self._initialized:
            self.value = 0
            self.__class__._initialized = True

# 方式二：模块级单例（Python 最推荐的写法）
# config.py
class _Config:
    def __init__(self):
        self.settings = {}
config = _Config()  # 模块级变量天然单例

# 方式三：装饰器实现
def singleton(cls):
    instances = {}
    @functools.wraps(cls)
    def wrapper(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return wrapper
线程安全：以上方式在多线程下不安全。如需线程安全单例，应加锁或使用模块级变量（模块加载是线程安全的）。
高频7. 描述符协议是什么？

描述符是一个实现了 __get__、__set__、__delete__ 中任意一个的类。property 本身就是一个描述符。

class ValidatedField:
    """数据描述符：带验证的属性"""

    def __init__(self, name, validator=None):
        self.name = name
        self.validator = validator

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return obj.__dict__.get(self.name)

    def __set__(self, obj, value):
        if self.validator:
            self.validator(value)
        obj.__dict__[self.name] = value

class User:
    age = ValidatedField("age", lambda v: assert v >= 0)

u = User()
u.age = 25  # 自动触发 __set__
面试追问：Python 的 classmethod、staticmethod、property、super 本质都是描述符。ORM 框架（SQLAlchemy）和 Pydantic 的字段验证都基于描述符协议。

三、进阶特性
高频1. GIL（全局解释器锁）是什么？对多线程有什么影响？

GIL（Global Interpreter Lock）是 CPython 的互斥锁，确保同一进程内同一时刻只有一个线程执行 Python 字节码。

场景多线程表现推荐方案
CPU 密集型受 GIL 限制，无法利用多核multiprocessing 多进程
I/O 密集型GIL 在 I/O 等待时释放，可并发多线程 或 asyncio

GIL 存在的原因：CPython 的内存管理（引用计数）不是线程安全的，GIL 简化了实现。但会导致：

  • 多线程无法真正并行执行 Python 代码
  • C 扩展可以手动释放 GIL（如 numpy 的计算）
最新进展：Python 3.13 引入了实验性的 free-threaded 模式（PEP 703），可关闭 GIL。但需要重新编译且生态兼容性仍在完善中。
高频2. Python 的垃圾回收机制？

Python GC 主要有三种机制：

① 引用计数（Reference Counting）—— 主力

  • 每个对象维护一个 ob_refcnt 引用计数
  • 引用 +1，引用消失 -1，归零立即回收
  • 优点：即时回收，确定性强
  • 缺点：无法处理循环引用

② 标记-清除（Mark and Sweep）—— 补充

  • 专门处理循环引用（如 A → B → A）
  • 定期扫描容器对象（list/dict/实例），标记可达对象，清除不可达的

③ 分代回收（Generational GC）—— 优化

  • 对象分三代：第0代（新建）、第1代、第2代
  • 新生代频繁扫描，老年代偶尔扫描
  • 经历过 GC 存活的对象晋升到下一代
import gc

# 手动触发 GC
gc.collect()

# 查看阈值
print(gc.get_threshold())  # (700, 10, 10)

# 关闭 GC（性能调优场景）
gc.disable()
面试追问：如何排查内存泄漏？→ 用 gc.get_objects() 统计对象数、用 tracemalloc 追踪分配点、用 objgraph 可视化引用关系。
高频3. 元类是什么？有什么用？

元类（Metaclass）是"类的类"。普通类的 type 是 type，元类可以自定义类的创建过程。

type 本身就是一个元类，所有类的元类默认是 type。

# type 的三参数形式：动态创建类
MyClass = type('MyClass', (), {'x': 1})
# 等价于：
# class MyClass:
#     x = 1

# 自定义元类：拦截类的创建
class SingletonMeta(type):
    _instances = {}
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class Database(metaclass=SingletonMeta):
    pass

# 也可用 __init_subclass__ 替代大部分元类场景
class Plugin:
    registry = []
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registry.append(cls)
面试建议：Python 3.6+ 的 __init_subclass__ 和 __set_name__ 能替代大部分元类用途。面试回答时优先提到这个更简单的替代方案，再补充元类。

高频6. Python 的 dataclass 和普通类的区别？
from dataclasses import dataclass, field

@dataclass

高频2. async/await 的原理和用法？

async def 定义协程函数，调用它返回一个协程对象（不立即执行）。await 挂起当前协程，让出控制权给事件循环，等待 awaitable 完成。

import asyncio

async def fetch_data(url):
    print(f"开始请求 {url}")
    await asyncio.sleep(1)  # 模拟I/O，让出控制权
    print(f"完成 {url}")
    return f"data from {url}"

# 并发执行多个协程
async def main():
    # 方式1：gather — 并发，保持顺序
    results = await asyncio.gather(
        fetch_data("url1"),
        fetch_data("url2"),
        fetch_data("url3"),
    )
    # 1秒完成（而非3秒），因为3个协程并发

    # 方式2：TaskGroup（Python 3.11+，推荐）
    async with asyncio.TaskGroup() as tg:
            t1 = tg.create_task(fetch_data("url4"))
            t2 = tg.create_task(fetch_data("url5"))
    # 任一 Task 异常会取消其他 Task

# 运行事件循环
asyncio.run(main())

高频1. Python 的内存管理模型？

Python 内存管理分三层：

  • pymalloc：Python 自带的内存分配器，管理 256KB 以下的小对象，使用内存池
  • C malloc/free：大于 256KB 的大对象直接走 C 层分配
  • 操作系统：最底层

内存池机制（Arena → Pool → Block）：

  • Arena（256KB）：向 OS 申请的大块内存
  • Pool（4KB）：Arena 内的子分配，同 Pool 内 Block 大小相同
  • Block：最小分配单元，按对象大小分类
高频2. Python 中的小整数缓存和字符串驻留？

小整数缓存：CPython 预缓存了 -5 到 256 的整数，这些对象在解释器启动时创建，全局复用。

字符串驻留（Interning）：

  • 符合标识符规则的字符串（只含字母数字下划线）自动驻留
  • 长度为 0 或 1 的字符串自动驻留
  • 编译期常量字符串会驻留

a is b  # True

c = "hello world"  # 含空格，不符合标识符规则

高频4. __slots__ 的作用和限制？

默认情况下，Python 实例通过 __dict__ 存储属性，这带来灵活性但消耗内存。使用 __slots__ 可固定属性集合，省去 __dict__。

# 不用 __slots__
class Point1:
    pass
p1 = Point1()
print(p1.__dict__)  # {} — 每个实例都有一个dict
p1.x = 1  # 可以动态添加属性

# 用 __slots__
class Point2:
    __slots__ = ('x', 'y')
p2 = Point2()
# p2.__dict__  # AttributeError — 没有 __dict__
p2.x = 1
# p2.z = 3  # AttributeError — 不能添加未声明的属性

优点：节省内存（大量实例时效果显著）、属性访问稍快。

限制：不能动态添加属性、不支持多继承（需所有父类都有 __slots__）、弱引用需要显式加入 '__weakref__'。

Agent2. 如何实现 LLM 调用的重试机制？
import asyncio
import functools

# 异步重试装饰器
def async_retry(max_retries=3, delay=1.0, backoff=2.0, exceptions=(Exception,)):
    def decorator(func):
        @functools.wraps(func)
        async def wrapper(*args, **kwargs):
            retry_delay = delay
            last_exc = None
            for attempt in range(max_retries + 1):
                try:
                    return await func(*args, **kwargs)
                except exceptions as e:
                    last_exc = e
                    if attempt < max_retries:
                        print(f"重试 {attempt+1}/{max_retries}: {e}")
                        await asyncio.sleep(retry_delay)
                        retry_delay *= backoff  # 指数退避
            raise last_exc
        return wrapper
    return decorator

@async_retry(max_retries=3, exceptions=(httpx.TimeoutException, httpx.HTTPStatusError))
async def call_llm(prompt):
    # ...调用 LLM API...
    pass

from pydantic import BaseModel
from typing import Callable

class Tool(BaseModel):
    name: str
    description: str
    func: Callable  # 实际不可序列化，示意

class ReActAgent:
    def __init__(self, llm, tools: list[Tool], max_iter=10):
        self.llm = llm
        self.tools = {t.name: t for t in tools}
        self.max_iter = max_iter

    async def run(self, query: str) -> str:
        messages = [{"role": "system", "content": self._build_system_prompt()}]
        messages.append({"role": "user", "content": query})

        for _ in range(self.max_iter):
            # 1. LLM 推理：决定下一步动作
            response = await self.llm.generate(messages)

            # 2. 解析输出：是否需要调用工具
            action = self._parse_action(response)

            if action["type"] == "final_answer":
                return action["answer"]

            # 3. 执行工具
            tool = self.tools[action["tool_name"]]
            observation = await tool.func(**action["args"])

            # 4. 将观察结果加入上下文
            messages.append({"role": "assistant", "content": response})
            messages.append({"role": "user", "content": f"Observation: {observation}"})

        return "达到最大迭代次数"

    def _build_system_prompt(self):
        tool_descs = "\n".join(
            f"- {t.name}: {t.description}" for t in self.tools.values()
        )
        return f"""你是一个 ReAct Agent。
可用工具:
{tool_descs}

请按以下格式回答:
Thought: 推理过程
Action: 工具名称
Action Input: JSON参数

或:

Final Answer: 最终回答"""

Agent7. Agent 的记忆系统如何用 Python 实现？
from abc import ABC, abstractmethod
from collections import deque
import json

# 抽象记忆接口
class BaseMemory(ABC):
    @abstractmethod
    async def add(self, message: dict): ...
    @abstractmethod
    async def load(self) -> list[dict]: ...
    @abstractmethod
    async def clear(self): ...

# 短期记忆：滑动窗口
class ConversationBufferMemory(BaseMemory):
    def __init__(self, max_messages=20):
        self.buffer = deque(maxlen=max_messages)

    async def add(self, message):
        self.buffer.append(message)

    async def load(self):
        return list(self.buffer)

# 带 Token 计数的记忆（控制上下文长度）
class TokenBufferMemory(ConversationBufferMemory):
    def __init__(self, max_tokens=4096):
        self.max_tokens = max_tokens
        self.messages = []
        self.token_counter = 0

    async def add(self, message):
        tokens = count_tokens(message["content"])
        self.messages.append(message)
        self.token_counter += tokens
        # 超限时淘汰旧消息
        while self.token_counter > self.max_tokens and self.messages:
            old = self.messages.pop(0)
            self.token_counter -= count_tokens(old["content"])

# 向量记忆：语义检索（长期记忆）
class VectorMemory(BaseMemory):
    def __init__(self, embedder, vector_store):
        self.embedder = embedder
        self.store = vector_store

    async def add(self, message):
        embedding = await self.embedder.embed(message["content"])
        await self.store.add(embedding, message)

    async def search(self, query, k=5):
        embedding = await self.embedder.embed(query)
        return await self.store.search(embedding, k)

高频3. 列表推导式 vs 生成器表达式的选择？
  • 列表推导式：[x for x in range(n)]，立即创建完整列表，占用内存
  • 生成器表达式：(x for x in range(n))，惰性生成，省内存

选择原则：需要多次遍历或需要 len()/索引 → 列表；只需遍历一次或数据量大 → 生成器。

from collections import OrderedDict

class LRUCache:
    """最近最少使用淘汰"""
    def __init__(self, capacity: int):
        self.cache = OrderedDict()
        self.capacity = capacity

    def get(self, key):
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)  # 访问后移到末尾（最近使用）
        return self.cache[key]

    def put(self, key, value):
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)  # 淘汰头部（最久未用）

手撕3. 手写异步限流器（Token Bucket）
import asyncio
import time

class AsyncRateLimiter:
    """令牌桶限流：每秒 rate 个请求，桶容量 capacity"""
    def __init__(self, rate: float, capacity: int = None):
        self.rate = rate
        self.capacity = capacity or int(rate)
        self.tokens = self.capacity
        self.last_time = time.monotonic()
        self.lock = asyncio.Lock()

    async def acquire(self):
        async with self.lock:
            now = time.monotonic()
            # 补充令牌
            elapsed = now - self.last_time
            self.tokens = min(self.capacity, self.tokens + elapsed * self.rate)
            self.last_time = now

            if self.tokens >= 1:
                self.tokens -= 1
                return True
            else:
                # 等待令牌恢复
                wait = (1 - self.tokens) / self.rate
                await asyncio.sleep(wait)
                self.tokens = 0
                return True

# 使用
limiter = AsyncRateLimiter(rate=10)  # 10 req/s

async def call_api():
    await limiter.acquire()
    return await http_request()
手撕4. 手写异步重试装饰器（指数退避）
import asyncio, functools, random

def async_retry(max_retries=3, base_delay=1, max_delay=60, exceptions=(Exception,)):
    def decorator(func):
        @functools.wraps(func)
        async def wrapper(*args, **kwargs):
            for attempt in range(max_retries + 1):
                try:
                    return await func(*args, **kwargs)
                except exceptions as e:
                    if attempt == max_retries:
                        raise
                    # 指数退避 + 抖动
                    delay = min(base_delay * (2 ** attempt), max_delay)
                    delay += random.uniform(0, delay * 0.1)
                    await asyncio.sleep(delay)
        return wrapper
    return decorator
手撕5. 手写生产者-消费者模型
import asyncio
import random

async def producer(queue, id):
    for i in range(5):
        item = f"producer-{id}-item-{i}"
        await queue.put(item)
        print(f"生产: {item}")
        await asyncio.sleep(random.uniform(0.1, 0.5))
    await queue.put(None)  # 哨兵值

async def consumer(queue, id):
    while True:
        item = await queue.get()
        if item is None:
            queue.task_done()
            break
        print(f"消费{'' if id=='' else f'-{id}'}: {item}")
        await asyncio.sleep(random.uniform(0.2, 0.8))
        queue.task_done()

async def main():
    queue = asyncio.Queue(maxsize=10)
    producers = [asyncio.create_task(producer(queue, i)) for i in range(3)]
    consumers = [asyncio.create_task(consumer(queue, i)) for i in range(2)]

    # 等待所有生产者完成
    await asyncio.gather(*producers)
    # 等待队列中所有任务完成
    await queue.join()
    # 取消消费者
    for c in consumers:
        c.cancel()

asyncio.run(main())

import asyncio

class AsyncPool:
    """协程池：限制同时运行的协程数"""
    def __init__(self, max_workers=10):
        self.semaphore = asyncio.Semaphore(max_workers)

    async def submit(self, coro):
        async with self.semaphore:
            return await coro

    async def map(self, coro_fn, iterable):
        tasks = [self.submit(coro_fn(item)) for item in iterable]
        return await asyncio.gather(*tasks)

# 使用：1000个任务，最多10个并发

        return (await client.get(url)).text

from pydantic import BaseModel
import inspect, json

class ToolRegistry:
    """工具注册与调度：从 Python 函数自动生成 Schema"""
    def __init__(self):
        self.tools = {}  # name → (func, schema)

    def register(self, func):
        sig = inspect.signature(func)
        params = {}
        for name, param in sig.parameters.items():
            params[name] = {
                "type": "string",  # 简化，实际需类型映射
                "description": param.annotation.__doc__ or "",
            }
        self.tools[func.__name__] = (func, {
            "name": func.__name__,
            "description": func.__doc__ or "",
            "parameters": {"type": "object", "properties": params},
        })
        return func

    async def execute(self, tool_name, **kwargs):
        func, _ = self.tools[tool_name]
        return await func(**kwargs)

    def get_schemas(self):
        return [schema for _, schema in self.tools.values()]
