FastAPI StreamingResponse 面试详解

从“返回一个响应”到“持续发送数据”：用异步生成器理解流式 HTTP、SSE 和任务生命周期。

目录： 是什么工作原理基本用法SSE生命周期面试题

1. StreamingResponse 是什么？

StreamingResponse 是 Starlette/FastAPI 提供的响应类型，用来把一个可迭代对象产生的数据分多次发送给客户端，而不是先把完整结果拼好再一次性返回。

普通响应
服务端先完成全部计算，再返回完整 body。
流式响应
服务端边计算边产生 chunk，客户端边接收边处理。
典型场景
AI 输出、日志、导出大文件、进度通知、SSE。

它解决的是“响应体如何传输”的问题；它本身不是 WebSocket，也不会自动创建后台任务。

2. 工作原理

请求到达 FastAPI→返回 StreamingResponse→ASGI 迭代 body_iterator→发送多个 http.response.body→more_body=False 结束

构造函数接收一个 content。这个 content 可以是同步迭代器、异步迭代器或生成器函数的结果。框架每次从中取出一个 chunk，编码成字节后交给 ASGI server（如 Uvicorn）发送。

StreamingResponse(content, status_code=200,
                   media_type="text/plain",
                   headers={...})

当迭代器结束时，框架发送最后一个结束标志。客户端是否“马上看到”每个 chunk，还可能受代理缓冲、压缩和客户端实现影响。

3. 基本用法

3.1 同步生成器

from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()

def rows():
    for i in range(5):
        yield f"row {i}\n"

@app.get("/rows")
def get_rows():
    return StreamingResponse(rows(), media_type="text/plain")

3.2 异步生成器

import asyncio

async def events():
    for i in range(5):
        await asyncio.sleep(1)
        yield f"progress={i}\n"

@app.get("/progress")
async def progress():
    return StreamingResponse(events(), media_type="text/plain")

注意：await asyncio.sleep() 让出事件循环；不要在 async generator 中直接执行很重的同步阻塞操作，否则会阻塞同一事件循环上的其他请求。

4. 与 SSE（Server-Sent Events）结合

SSE 是建立在普通 HTTP 流之上的文本协议。每条消息通常以 data: 开头，并以两个换行符分隔：

data: {"type":"progress","value":50}


import json
from fastapi.responses import StreamingResponse

async def sse_stream(queue):
    while True:
        data = await queue.get()
        yield f"data: {json.dumps(data, ensure_ascii=False)}\n\n"
        if data.get("type") == "done":
            return

return StreamingResponse(
    sse_stream(queue),
    media_type="text/event-stream",
    headers={
        "Cache-Control": "no-cache",
        "X-Accel-Buffering": "no",
    },
)
配置作用
media_type="text/event-stream"告诉浏览器这是 SSE 流。
data: ...\n\n符合 SSE 消息边界格式。
Cache-Control: no-cache避免缓存旧事件。
X-Accel-Buffering: no常用于 Nginx，避免代理把多个事件攒在一起。

5. 结合后台 task 的生命周期

task = asyncio.create_task(do_work(queue))

async def _event_stream():
    while True:
        try:
            data = await asyncio.wait_for(queue.get(), timeout=300)
            yield f"data: {json.dumps(data)}\n\n"
            if data.get("type") == "done":
                await task       # 确认后台任务真的完成，并传播异常
                return            # 结束异步生成器，关闭响应流
        except asyncio.TimeoutError:
            yield 'data: {"type":"timeout"}\n\n'
            return

await task 和 return 作用不同：前者等待任务完成，后者结束生成器。若只 return，可能响应流已经关闭，但后台任务还没完成或其异常没有被观察到。

生产环境要点：还应考虑客户端断开连接时取消后台任务、释放资源，以及避免任务创建后无人持有引用导致异常难以追踪。

6. StreamingResponse 与其他技术的区别

技术通信方向特点适用场景
StreamingResponse / SSE服务端 → 客户端HTTP 长连接，简单、可被浏览器 EventSource 使用AI 输出、进度、通知
普通 JSON Response请求 → 一次响应简单，客户端处理最容易短请求、完整结果
WebSocket双向持续双向通信，协议复杂度更高聊天、协作、实时控制
BackgroundTasks不是传输协议请求响应后执行任务发邮件、轻量清理

7. 面试高频问答

Q：StreamingResponse 和普通 Response 的核心区别？
A：普通响应通常先得到完整 body 再返回；StreamingResponse 接收迭代器，边产生边发送，降低首字节延迟和内存峰值。
Q：为什么要用 async generator？
A：它可以在每次 yield 之间 await 异步 I/O，使事件循环在等待期间处理其他请求；每次 yield 就是一个可发送的响应片段。
Q：StreamingResponse 会自动把函数放到后台吗？
A：不会。它只是把响应 body 变成流。若需要后台任务，必须显式使用 asyncio.create_task、任务队列或任务系统。
Q：yield 一次是不是一定对应客户端收到一次？
A：不一定。服务器、TCP、反向代理、压缩层都可能合并或缓冲数据；协议上是多个 chunk，但客户端观察到的边界不保证完全一致。
Q：SSE 每条消息为什么是两个换行符？
A：一个换行结束字段，空行表示一条 SSE event 结束；缺少空行时客户端可能继续等待更多内容。
Q：超时后 return 会发生什么？
A：异步生成器结束，StreamingResponse 停止向客户端发送数据；但它不一定自动取消你另外创建的后台 task，需要显式取消并处理清理。

8. 一句话总结

StreamingResponse = 把一个同步/异步可迭代对象包装成 HTTP 流，框架逐个消费其 yield 的数据并发送给客户端；SSE 则是在这个流上约定了事件格式。

面试表达建议：先讲“边生成边传输”，再讲“异步生成器与 ASGI body chunks”，最后补充 SSE 格式、代理缓冲、断开取消和异常传播。
