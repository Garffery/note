1装饰器是什么

一句话定义

装饰器是一个接受函数作为参数、返回新函数的可调用对象。它让你在不修改原函数代码的情况下，给函数"穿上"额外的行为。本质上是 AOP（面向切面编程）在 Python 中的实现。

等价关系

@decorator def func(): ... # 完全等价于： func = decorator(func)

装饰器的三个核心要素

要素说明
接受函数被装饰的函数作为参数传入
返回新函数返回一个包装后的函数（或其他可调用对象）
不改变调用方式调用方仍然用 func() 的方式调用，感知不到装饰器的存在

执行时机

def dec(func): print("装饰器执行了") # ← 这行在**定义时**就执行！ def wrapper(*args, **kwargs): print("wrapper 执行了") # ← 这行在**调用时**才执行 return func(*args, **kwargs) return wrapper @dec def hello(): print("hello") # 输出: "装饰器执行了" ← 定义 @dec 时就已经执行了！ # hello() 还没被调用，但 dec(hello) 已经执行完了

面试重点 装饰器在函数定义时执行，不是在函数调用时执行。wrapper 里的逻辑才在调用时执行。

2函数装饰器（无参数）

基础写法

import functools import time def timer(func): @functools.wraps(func) # 保留原函数元信息 def wrapper(*args, **kwargs): start = time.perf_counter() result = func(*args, **kwargs) elapsed = time.perf_counter() - start print(f"[{func.__name__}] 耗时 {elapsed:.4f}s") return result return wrapper @timer def compute(n): return sum(range(n)) compute(10000) # [compute] 耗时 0.0003s

多个装饰器叠加

@dec1 @dec2 @dec3 def func(): ... # 等价于：func = dec1(dec2(dec3(func))) # 执行顺序：从下往上包装，从上往下执行 # 即定义时：dec3 → dec2 → dec1（从里到外包） # 调用时：dec1 → dec2 → dec3 → 原函数（从外到里执行）

3函数装饰器（带参数）

三层嵌套

带参数的装饰器本质是"装饰器工厂"——外层接收配置参数，返回真正的装饰器。

def retry(max_attempts=3, delay=1): # ← 第一层：接收装饰器参数 def decorator(func): # ← 第二层：接收被装饰函数 @functools.wraps(func) def wrapper(*args, **kwargs): # ← 第三层：包装调用逻辑 for attempt in range(max_attempts): try: return func(*args, **kwargs) except Exception as e: if attempt == max_attempts - 1: raise time.sleep(delay) return wrapper return decorator @retry(max_attempts=5, delay=2) # 带参数的写法 def fetch_data(url): ...

带参 vs 无参的执行过程

写法等价展开
@timer func = timer(func)
@retry(max=3) func = retry(max=3)(func) —— 先调 retry(max=3) 返回 decorator，再 decorator(func) 返回 wrapper

4functools.wraps 与元信息保留

没有 wraps 会怎样？

def bad_decorator(func): def wrapper(*args, **kwargs): return func(*args, **kwargs) return wrapper @bad_decorator def say_hello(): """说你好""" pass print(say_hello.__name__) # "wrapper" ← 不是 "say_hello"！ print(say_hello.__doc__) # None ← 丢了！

加上 wraps

def good_decorator(func): @functools.wraps(func) # ← 关键 def wrapper(*args, **kwargs): return func(*args, **kwargs) return wrapper @good_decorator def say_hello(): """说你好""" pass print(say_hello.__name__) # "say_hello" ✅ print(say_hello.__doc__) # "说你好" ✅

wraps 复制了哪些属性？

# functools.wraps 底层调用 update_wrapper，复制这些： WRAPPER_ASSIGNMENTS = ('__module__', '__name__', '__qualname__', '__doc__', '__annotations__') WRAPPER_UPDATES = ('__dict__',)

面试重点 面试官看到装饰器代码没加 @wraps —— 直接扣分。这体现的是工程素养。

5类装饰器（无参数）

核心机制

用 __init__ 接收被装饰函数，用 __call__ 实现包装逻辑。

class Logger: def __init__(self, func): # func = 被装饰的原始函数 self.func = func functools.update_wrapper(self, func) # 保留元信息 def __call__(self, *args, **kwargs): # 调用时走这里 print(f"[LOG] 调用 {self.func.__name__}") start = time.perf_counter() result = self.func(*args, **kwargs) print(f"[LOG] 耗时 {time.perf_counter() - start:.3f}s") return result @Logger def compute(n): return sum(range(n)) compute(10000) # [LOG] 调用 compute # [LOG] 耗时 0.002s

等价展开

compute = Logger(compute) —— 先实例化 Logger（调用 __init__），再把这个实例赋值给 compute。之后 compute() 其实是在调 Logger 实例的 __call__。

对比函数装饰器

# 函数装饰器版本（等价） def Logger(func): @functools.wraps(func) def wrapper(*args, **kwargs): print(f"[LOG] 调用 {func.__name__}") result = func(*args, **kwargs) return result return wrapper

6类装饰器（带参数）⭐

这才是生产中最常用的形式

带参数的类装饰器只需要两层（相比之下函数装饰器需要三层），可读性大幅提升。

class Retry: def __init__(self, max_attempts=3, delay=1): """← 这里接收装饰器自身的配置参数""" self.max_attempts = max_attempts self.delay = delay def __call__(self, func): """← 这里才拿到被装饰的函数""" @functools.wraps(func) def wrapper(*args, **kwargs): for attempt in range(self.max_attempts): try: return func(*args, **kwargs) except Exception as e: if attempt == self.max_attempts - 1: raise print(f"第 {attempt + 1} 次失败: {e}，{self.delay}s 后重试") time.sleep(self.delay) return wrapper @Retry(max_attempts=3, delay=2) # 配置重试参数 def fetch_data(url): ... @Retry(max_attempts=5) # 不同参数，不同装饰行为 def process_task(task): ...

执行过程详解

@Retry(max_attempts=3, delay=2) def fetch_data(url): ... # 等价于： # fetch_data = Retry(max_attempts=3, delay=2)(fetch_data) # └──────┬──────┘ └────┬────┘ # ① 调用 __init__ ② 调用 __call__ # → 返回 Retry 实例 → 返回 wrapper 函数

函数装饰器 vs 类装饰器：嵌套层数对比

函数装饰器类装饰器
无参数 2 层 2 层（__init__ + __call__）
有参数 3 层（工厂 → 装饰器 → wrapper） 2 层（__init__ + __call__）

7带状态的类装饰器

函数装饰器维护状态很别扭

# 函数装饰器：必须用 nonlocal def count_calls(func): count = 0 # 自由变量 @functools.wraps(func) def wrapper(*args, **kwargs): nonlocal count # ← 必须加 nonlocal，否则 UnboundLocalError count += 1 print(f"第 {count} 次调用") return func(*args, **kwargs) return wrapper

类装饰器：self 直接存，清晰自然

class CountCalls: def __init__(self, func): self.func = func self.count = 0 # 直接用 self，不需要 nonlocal functools.update_wrapper(self, func) def __call__(self, *args, **kwargs): self.count += 1 print(f"第 {self.count} 次调用 {self.func.__name__}") return self.func(*args, **kwargs) def reset(self): # ← 函数装饰器做不到的：暴露额外方法 self.count = 0 @CountCalls def say_hello(): print("hello") say_hello() # 第 1 次调用 say_hello say_hello() # 第 2 次调用 say_hello say_hello.reset() # ← 直接访问装饰器实例的方法 say_hello() # 第 1 次调用 say_hello

多状态场景：类装饰器 > 函数装饰器

class RateAndCache: def __init__(self, max_calls=5, ttl=60): self.max_calls = max_calls self.ttl = ttl self.tokens = max_calls # 令牌桶 self.last_refill = time.monotonic() self.cache = {} # 缓存 self.call_count = 0 # 调用统计 self.errors = [] # 错误记录 def __call__(self, func): @functools.wraps(func) def wrapper(*args, **kwargs): self.call_count += 1 # 1. 检查缓存 cache_key = (args, tuple(sorted(kwargs.items()))) if cache_key in self.cache: return self.cache[cache_key] # 2. 令牌桶限流 self._refill() if self.tokens <= 0: raise RuntimeError("限流，稍后重试") self.tokens -= 1 # 3. 执行 return func(*args, **kwargs) return wrapper def _refill(self): ... def stats(self): # 查看统计 return {"calls": self.call_count, "errors": self.errors} def clear_cache(self): # 清缓存 self.cache.clear()

函数装饰器要维护这 4 个状态变量，需要用闭包 + nonlocal 操作 4 个自由变量，代码可读性极差。类装饰器用 self.xxx 全部搞定，还能暴露 stats()、clear_cache() 等工具方法。

8类装饰器 vs 函数装饰器对比

维度函数装饰器类装饰器
无参数写法 2 层嵌套 __init__ + __call__
带参数写法 3 层嵌套（容易混乱） 2 层（分层清晰）⭐
状态维护 闭包 + nonlocal，状态多了很乱 self.xxx，多少个状态都清晰
暴露额外方法 不舒服（技术上可行但不优雅） ✅ 直接添加到类中
可测试性 需要暴露内部函数 ✅ 直接测试实例方法
可继承 ❌ 不能 ✅ 可以子类化复用
性能 略快（函数调用开销小） 略慢（实例化 + __call__）
适用场景 简单、无状态的装饰逻辑 复杂、有状态、需要复用的场景

选择指南

  • 状态变量 ≤ 1 个，装饰器不带参数 → 函数装饰器
  • 状态变量 ≥ 2 个，或装饰器带参数 → 类装饰器
  • 需要暴露方法（如 reset()、stats()）→ 必须类装饰器
  • 需要继承复用 → 必须类装饰器

9functools.partial 偏函数

一句话

偏函数就是把一个函数的一部分参数提前写死，生成一个新函数。

from functools import partial def add(a, b, c): return a + b + c add_100 = partial(add, 100) # 把 a 固定为 100 print(add_100(20, 3)) # 123，等价于 add(100, 20, 3)

原理（简化版）

class partial: def __init__(self, func, /, *args, **kwargs): self.func = func self.args = args self.keywords = kwargs def __call__(self, /, *args, **kwargs): merged_kwargs = {**self.keywords, **kwargs} return self.func(*self.args, *args, **merged_kwargs)

partial vs lambda

partiallambda
元信息保留✅ __name__、.func 都在❌ 全成 <lambda>
可 pickle 序列化✅ 支持❌ 不支持
性能略快（C 实现）略慢
调试调用栈清晰调用栈混乱

重要 在分布式 / multiprocessing 场景下，lambda 不可 pickle 会直接导致程序崩溃，必须用 partial。

Agent 开发中的实际用例

# 预设 LLM 调用参数，避免每次重复传参 call_gpt4 = partial( openai.chat.completions.create, model="gpt-4", temperature=0.3, max_tokens=4096, ) # 实际调用时只传必要参数 result = call_gpt4(messages=[{"role": "user", "content": "你好"}])

10lambda 默认参数陷阱

经典陷阱：闭包延迟绑定

# ❌ 陷阱 funcs = [lambda: i for i in range(3)] print([f() for f in funcs]) # [2, 2, 2] ← 全是最后一个值！

原因：闭包绑定变量名，不绑定值

# 循环结束后 i = 2，三个 lambda 的 i 都指向同一个变量 # 调用时去查 i 的值，都是 2 import dis dis.dis(funcs[0]) # LOAD_GLOBAL 0 (i) ← 加载全局变量 i，不是值！

解法：默认参数在定义时求值

# ✅ 用默认参数"提前绑定"当前值 funcs = [lambda i=i: i for i in range(3)] print([f() for f in funcs]) # [0, 1, 2] ✅ # Python 的默认参数在「函数定义时」求值，不是「调用时」 # i=i 中的右边 i 在定义那一刻就固定成了当时的值 f0 = funcs[0] print(f0.__defaults__) # (0,) ← 值在定义时就存下来了

字节码层面的区别（面试加分）

延迟绑定 lambda: i默认参数 lambda i=i: i
字节码LOAD_GLOBAL i（每次查变量）LOAD_FAST i（读局部变量，来自 __defaults__）
取值时机调用时定义时

场景一：LLM 调用重试（类装饰器）

class LLMRetry: RETRYABLE = (RateLimitError, Timeout, ConnectionError) def __init__(self, max_attempts=3, backoff=2): self.max_attempts = max_attempts self.backoff = backoff self.total_attempts = 0 # 状态统计 def __call__(self, func): @functools.wraps(func) def wrapper(*args, **kwargs): for i in range(self.max_attempts): self.total_attempts += 1 try: return func(*args, **kwargs) except self.RETRYABLE as e: if i == self.max_attempts - 1: raise await asyncio.sleep(self.backoff ** i) # 指数退避 return wrapper def stats(self): return {"total_retry_attempts": self.total_attempts}

场景二：工具调用计时 + 日志（函数装饰器）

def tool_logger(func): @functools.wraps(func) def wrapper(*args, **kwargs): start = time.perf_counter() try: result = func(*args, **kwargs) elapsed = time.perf_counter() - start logger.info(f"tool={func.__name__} status=ok cost={elapsed:.3f}s") return result except Exception as e: elapsed = time.perf_counter() - start logger.error(f"tool={func.__name__} status=error cost={elapsed:.3f}s error={e}") raise return wrapper

场景四：异步工具调用限流（类装饰器）

class AsyncRateLimit: def __init__(self, max_per_second=5): self.max_per_second = max_per_second self._tokens = max_per_second self._last_refill = time.monotonic() self._lock = threading.Lock() def __call__(self, func): @functools.wraps(func) async def wrapper(*args, **kwargs): with self._lock: now = time.monotonic() self._tokens = min( self.max_per_second, self._tokens + (now - self._last_refill) * self.max_per_second ) self._last_refill = now if self._tokens < 1: wait = (1 - self._tokens) / self.max_per_second await asyncio.sleep(wait) self._tokens = 0 else: self._tokens -= 1 return await func(*args, **kwargs) return wrapper

12面试问答速查

Q1: 装饰器的本质是什么？

装饰器是一个接受函数作为参数、返回新函数的可调用对象。本质是 AOP（面向切面编程），在函数定义时执行。语法糖 @dec 等价于 func = dec(func)。

Q2: 为什么必须用 @wraps？

因为装饰器返回的是 wrapper 函数，原函数的 __name__、__doc__、类型注解等元信息会丢失。@wraps(func) 将这些信息从原函数复制到 wrapper 上，保持函数签名不变。这对调试、文档生成、IDE 提示都至关重要。

Q3: 带参数的装饰器怎么写？

函数方式：三层嵌套（外层收参数 → 中层收函数 → 内层包装逻辑）。类方式：__init__ 收参数 → __call__ 收函数。类方式只需要两层，可读性更好，是带参数装饰器的推荐写法。

Q4: 类装饰器什么时候必须用？

① 装饰器需要维护多个状态变量（限流 + 缓存 + 统计） ② 需要暴露额外方法（如 reset()、stats()） ③ 需要继承复用。其余场景函数装饰器足矣。

Q5: 能装饰类吗？

可以。装饰器接受一个类，可以修改类的属性或方法，返回新的类。典型场景：@dataclass、@functools.total_ordering、注册类到全局表等。

Q6: 多个装饰器叠加的执行顺序？

@d1 @d2 @d3 def f(): 等价于 f = d1(d2(d3(f)))。定义时从下往上包装（d3 → d2 → d1），调用时从上往下执行（d1 → d2 → d3 → 原函数）。离函数最近的装饰器最后执行包装，最先执行内部的 wrapper 逻辑。

Q7: partial 和 lambda 有什么区别？什么时候用 partial？

partial 保留原函数元信息、可 pickle 序列化、调试友好、C 实现更快。Lambda 不可 pickle，在 multiprocessing / 分布式场景下直接崩溃。需要序列化或大量参数预设时，必须用 partial。

Q8: 装饰器是运行时还是编译时执行的？

装饰器本身在模块加载时（函数定义时）执行，不是调用时。但 wrapper 内部的逻辑在调用时才执行。这意味着装饰器里的耗时操作（如网络请求）会在 import 时就触发，不应该放在装饰器的顶层。

Q9: 装饰器和上下文管理器什么关系？

装饰器给函数"穿上"横切逻辑（AOP），上下文管理器给代码块"包上"前后处理。两者可组合使用：

def timing(func): @wraps(func) def wrapper(*args, **kwargs): with stopwatch(): # 用上下文管理器实现计时 return func(*args, **kwargs) return wrapper

Q10: 装饰器在 asyncio 中怎么写？

注意区分被装饰的是同步函数还是异步函数：

# 装饰异步函数 → wrapper 也要 async def async_retry(max_attempts=3): def decorator(func): @wraps(func) async def wrapper(*args, **kwargs): for i in range(max_attempts): try: return await func(*args, **kwargs) except Exception: if i == max_attempts - 1: raise await asyncio.sleep(1) return wrapper return decorator
